# چک‌لیست دستی رفع مشکل sitemap سایت tehnet.ir

> این سند فقط راهنمای عمل دستی شماست؛ سیستم هیچ تغییری روی سایت نمی‌دهد. زمان تخمینی: ۵ دقیقه.

## مشکل فعلی (تأییدشده در ۲۰۲۶-۰۹-۲۹)
- `https://tehnet.ir/sitemap.xml` → ریدایرکت ۳۰۱ به `wp-sitemap.xml`
- `https://tehnet.ir/wp-sitemap.xml` → **404**
- فایل `robots.txt` هیچ خط `Sitemap:` ندارد
- نتیجه: موتورهای جست‌وجو هیچ نقشهٔ سایتی از tehnet.ir دریافت نمی‌کنند.

## علت ریشه‌ای (تشخیص داده‌شده بدون دست‌زدن به سایت)
- ریدایرکت را **خودِ وردپرس** صادر می‌کند (هدر `X-Redirect-By: WordPress`) — پس مشکل از Cloudflare نیست.
- هیچ افزونهٔ سئویی (Yoast/RankMath/…) نصب نیست — فهرست namespace های REST فقط WooCommerce و Jetpack را نشان می‌دهد.
- پس نتیجه: **نقشهٔ سایت هستهٔ وردپرس عمداً یا اشتباهاً غیرفعال شده** (معمول‌ترین دو علت: تیکِ «جلوگیری از ایندکس موتورهای جست‌وجو» در تنظیمات، یا فیلتر `wp_sitemaps_enabled` در کد قالب/mu-plugin/snippet) و ریدایرکتِ باقی‌مانده به مقصد 404 می‌رود.

## اقدام دقیق (در wp-admin، به‌ترتیب)
1. **تنظیمات ← خواندن (Reading):** اگر تیک «جلوگیری از ایندکس موتورهای جست‌وجو» خورده، بردارید و ذخیره کنید.
2. اگر تیک نبود: **نمونه‌کارها ← پوستهٔ فرزند/کدهای سفارشی ← Code Snippets (یا mu-plugins):** دنبال `wp_sitemaps_enabled` یا `wp_sitemaps_remove_rewrite_rules` بگردید و آن snippet را غیرفعال/حذف کنید.
3. **تنظیمات ← پیوندهای یکتا (Permalinks):** فقط یک‌بار «ذخیره» کنید (قواعد rewrite فلوش می‌شود).
4. نشانی `https://tehnet.ir/wp-sitemap.xml` را در مرورگر باز کنید (یا از دکمهٔ زیر).
5. اگر 200 شد: در **افزونه/تنظیمات robots** (یا از طریق میزبان) این خط را به `robots.txt` اضافه کنید:
   `Sitemap: https://tehnet.ir/wp-sitemap.xml`
6. ریدایرکت `sitemap.xml→wp-sitemap.xml` بعد از کارکردن مقصد، بی‌ضرر است؛ در صورت تمایل حذفش کنید (نیازی نیست).

## نتیجهٔ مورد انتظار
- `wp-sitemap.xml` = **200** و یک XML با `<urlset>` (یا `<sitemapindex>`)
- `robots.txt` شامل خط `Sitemap:`

## راستی‌آزمایی بعد از تغییر
1. در پنل: **صفحهٔ سئو ← سایت tehnet.ir ← «اجرای اسکن»** — باید sitemap «ok» شود و شمارش نشانی‌ها > 0؛ اسکن جدید در تاریخچه ثبت می‌شود (اسکن قبلی حفظ می‌شود).
2. بیرون: `curl -I https://tehnet.ir/wp-sitemap.xml` باید `200` بدهد.
3. بعد از ۲۴–۷۲ ساعت در Search Console (بعد از اتصال credential در پنل) وضعیت Coverage بهتر می‌شود.

**نکتهٔ mytel.one:** همین اسکن را در پنل برای mytel.one هم اجرا کنید؛ اگر همین مشکل بود، همین چک‌لیست روی آن سایت هم اعمال شود.
