# HOST ISOLATION RULE — Tolid-Mohtava (NON-NEGOTIABLE, overrides all convenience)

این میزبان میزبان سرویس‌های تولیدی دیگر است. بالاترین قانون زیرساختی:

**Tolid-Mohtava هرگز نباید هیچ سرویس/تونل/پورت/شبکه/قانون فایروال/کانتینر/پروکسی/VPN/پروسسِ غیرمرتبط را تغییر دهد، ری‌استارت کند، پیکربندی مجدد کند، حذف/پرون کند، ریمپ کند یا مختل سازد.**

اپلیکیشن فقط داخل منابعِ صریحاً متعلق به Tolid-Mohtava کار می‌کند.

## قواعد اجرایی

1. **فقط منابع پروژه** — مخزن، کانفیگ، لاگ/کش/دیتای پروژه، کانتینر/شبکه/والیوم با نام/لیبل مالکیت پروژه (`com.tolid-mohtava.project=true`)، پورت‌های مصوب. «دسترسی‌پذیر بودن» مالکیت نیست.
2. **کانتینرهای غیرمرتبط دست‌نخورده** — stop/restart/rm/kill/update ممنوع؛ تداخل پورت → گزارش `PORT_CONFLICT_EXTERNAL`، نه حل با دست‌زدن به دیگری.
3. **پرون سراسری داکر مطلقاً ممنوع** — `docker system prune` و مشابه‌ها هرگز؛ پاک‌سازی فقط هدفمند روی منابع دارای لیبل پروژه.
4. **مالکیت پورت قبل از bind** — بررسی فقط-خواندنی (netstat/Get-NetTCPConnection/docker ps)؛ پورت اشغال‌شده = خارجی/فقط-خواندنی.
5. **تونل‌های موجود تغییرناپذیر** — Tailscale/WireGuard/OpenVPN/Xray/SSH/Cloudflare غیرمرتبط: قطع/ری‌استارت/ری‌اث/ریکانیف/حذف ممنوع.
6. **Tailscale = زیرساخت مشترک، حالت پیش‌فرض READ-ONLY** — بازرسی status/ip مجاز؛ تغییر ACL/DNS/route/exit-node/Serve/Funnel/گواهی/احراز فقط با مجوز صریح مالک برای همان تغییر مشخص. اگر گواهی HTTPS نبود → فال‌بک تأییدشدهٔ IP خصوصی، بدون ریکانیفگ سراسری.
7. **فایروال** — سیاست سراسری دست‌نخورده؛ قانون پروژه‌ای فقط با نام یکتا شامل «Tolid-Mohtava» و فقط برای پورت/پروسس خود پروژه (نمونه فعلی: `Tolid-Mohtava-Tailnet-Only` = TCP/8767، Remote `100.64.0.0/10`).
8. **شبکه میزبان دست‌نخورده** — گیت‌وی/DNS/جدول روت/اینترفیس/NAT/فورواردینگ/system-proxy ممنوع.
9-10. **ایزوله‌سازی داکر** — شبکه اختصاصی (مثل `tolid_mohtava_internal`)، والیوم اختصاصی؛ مونت Docker socket/ریوت/دایرکتوری حساس ممنوع؛ حداقل امتیاز.
11. **فایل‌سیستم میزبان** — نوشتن فقط در مخزن/والیوم/دایرکتوری ران‌تایم پروژه؛ تغییر کانفیگ سرویس دیگر/ریجیستری/پروفایل‌ها ممنوع.
12-13. **بدون ری‌استارت سرویس میزبان** — reboot/Restart-Service/داکمون/سرویس Tailscale/شبکه ممنوع؛ فقط کانتینر خود پروژه. مشکل داکر → `HOST_DOCKER_INTERVENTION_REQUIRED`.
14. **پورت‌های موجود = خارجی** — به‌ویژه `8766 AutoClaw`؛ ناامن بودن → فقط گزارش `EXTERNAL HOST FINDING`، بدون اصلاح.
15-16. **پری‌فلایت/پست‌فلایت** — قبل از هر deploy خط‌پایهٔ فقط-خواندنی (کانتینرها، پورت‌ها، شبکه‌ها، والیوم‌ها، حافظه/دیسک، وضعیت Tailscale) و مقایسهٔ بعدی؛ هر تغییر جانبی غیرمنتظره → توقف، `HOST_ISOLATION_FAIL`، بازگردانی فقط تغییرات پروژه‌ایِ امن.
17-18. **سقف منابع و ترتیب تنزل** — محدودیت memory/CPU/لاگ‌روتیشن/کش؛ در فشار منبع: اول کارهای پس‌زمینهٔ اختیاری، بعد مدیا/کش، بعد AI اختیاری؛ هرگز آزادسازی با کشتن سرویس دیگر.
19. **تعارض زیرساختی = Fail-Closed** — نیاز به تغییر مؤلفهٔ غیرمرتبط → انجام نده؛ `BLOCKED_BY_HOST_ISOLATION` + منبع متنازع + جایگزین امن.
20-21. **تگ مالکیت؛ نامِ مشابه مالکیت نیست** — مالکیت فقط با compose/لیبل/مستند/دستور صریح مالک.
22-23. **یافتهٔ بیرونی فقط گزارش؛ پاک‌سازی فقط پروژه‌ای.**
24. **دروازهٔ پذیرش هر deploy:** HOST-001..010 (کانتینر/پورت/تونل/Tailscale/فایروال غیرمرتبط دست‌نخورده؛ داکمون بدون ری‌استارت؛ بدون پرون سراسری؛ ایزولاسیون و سقف منابع پروژه؛ سلامت سرویس‌های دیگر). هر گاته شکست = deploy FAIL حتی اگر خود پروژه کار کند.
25. **قالب گزارش هر deploy:** `HOST ISOLATION: PASS/FAIL` + کانتینرهای تغییرکردهٔ پروژه + «کانتینر/پورت/تونل/قانون‌فایروال غیرمرتبط تغییرکرده: 0 (الزامی)» + «داکمون ری‌استارت: NO» + «پرون سراسری: NO» + یافته‌های بیرونی (بدون اصلاح).

## وضعیت فعلی (خط‌پایهٔ ثبت‌شده ۱۴۰۵/۰۷/۰۹)

- Tolid-Mohtava روی این میزبان از داکر استفاده نمی‌کند (پنل = پروسهٔ پایتون روی `127.0.0.1:8767` + پراکسی خصوصی روی `100.87.126.12:8767`).
- Tailscale فقط خوانده شده؛ Serve/Funnel/ACL/DNS دست‌نخورده.
- تنها قانون فایروال پروژه‌ای: `Tolid-Mohtava-Tailnet-Only` (TCP/8767 ← 100.64.0.0/10).
- **EXTERNAL HOST FINDING (فقط گزارش، بدون اصلاح):** `AutoClaw` روی `0.0.0.0:8766` گوش می‌دهد (از LAN پاسخ می‌دهد).
