# راهنمای بازیابی فاجعه (DISASTER RECOVERY) — v1.0.0-local-ready

> فقط سناریوهایی که واقعاً پیاده‌سازی و آزمون شده‌اند. هر جا محدودیت داریم، صادقانه نوشته شده.

## قاعدهٔ طلایی

1) آرام بمانید 2) پشتیبان اخیر را پیدا کنید 3) پنل را ببندید 4) بازگردانی 5) باز کردن با `Open-Panel.cmd`.
پشتیبان‌ها: `outputs\backups\tolid-<yyyyddmm-hhmmss>\` (هر پوشه + فایل checksum).

## ۱. خرابی دیتابیس (content.sqlite)

**نشانه:** پنل بالا می‌آید اما «خواندن اطلاعات ناموفق بود» یا خطای دیتابیس در صفحهٔ سلامت.

1. پنل را ببندید.
2. از `outputs\panel\data\content.sqlite` یک کپی دستی نگه دارید (حتی خراب — برای بررسی).
3. جدیدترین پشتیبان سالم را برگردانید:
   ```powershell
   powershell -ExecutionPolicy Bypass -File setup\Restore-TolidMohtava.ps1 -From outputs\backups\tolid-<نام‌پوشه>
   ```
4. پنل را باز کنید ← صفحهٔ سلامت ← «Database» باید سبز باشد.

**ازدست‌رفته:** هر چیزی که بعد از آخرین پشتیبان ثبت شده باشد. **محدودیت:** بازگردانی جایگزینِ کامل دیتابیس است؛ ادغام دو دیتابیس پیاده‌سازی نشده.

## ۲. حذف تصادفی پروژه

- **آرشیوشده؟** چیزی حذف نشده: پروژه‌ها ← «نمایش آرشیو» ← «بازگردانی از آرشیو».
- **حذف قطعی (با تایپ «حذف»)؟** از رابط کاربری بازگشت ندارد؛ فقط از پشتیبان قبلی قابل بازگردانی است (به‌همراه کل دیتابیس آن زمان — بقیهٔ تغییرات بعد از پشتیبان هم برمی‌گردد/از بین می‌رود).
- **پست‌های بیرونی (وردپرس/شبکه‌ها) هرگز با حذف پروژه حذف نمی‌شوند** — این تضمین شده است.
- فایل‌های RAW رسانه در حذف قطعی پروژه پاک می‌شوند (رفتار موردنظر)؛ نسخهٔ پشتیبان با `-IncludeMedia` آن‌ها را دارد.

## ۳. پنل بالا نمی‌آید

1. `Open-Panel.cmd` دوباره — پورت 8766 اشغال؟ خودکار 8767 (نشانی‌ای که مرورگر باز کرده درست است).
2. پیام کنسول:
   - «Python not found» ← `setup\Setup-TolidMohtava.ps1` (نصب، داده‌ها را نمی‌ترکاند).
   - خطای bind/دسترسی پورت ← سرویس خارجی روی آن پورت است؛ 8767/8768 را از مرورگر امتحان کنید.
   - خطای دیتابیت ← سناریوی ۱.
3. کد پنل خراب شده (مثلاً بعد از تغییرات دستی)؟ به کامیت پایدار برگردید — [STABLE-ROLLBACK-POINT](STABLE-ROLLBACK-POINT.fa.md). دیتابیس و رسانه‌ها جدا از کدند؛ با git برنمی‌گردند و از بین نمی‌روند.

## ۴. خرابی LM Studio

- پنل سالم می‌ماند؛ فقط کارهای AI با «BLOCKED_BY_DEPENDENCY» ناموفق می‌شوند (صادقانه، بدون دادهٔ جعلی).
- رفع: LM Studio را باز کنید ← سرور محلی روی `127.0.0.1:1234` ← لود مدل `qwen2.5-7b-instruct` ← در پنل «تلاش دوباره».
- مدل حذف/خراب شده؟ در LM Studio دوباره بگیرید؛ نام مدل در تنظیمات ← بخش هوش مصنوعی قابل تغییر است.

## ۵. خرابی FFmpeg

- تشخیص از صفحهٔ سلامت (FFmpeg/FFprobe قرمز).
- رفع: `setup\Setup-TolidMohtava.ps1` (نصب/تعمیر بدون دست‌زدن به داده‌ها) یا `winget install Gyan.FFmpeg`.
- فایل خاصی خطا می‌دهد؟ اگر فایل واقعاً خراب/بی‌صدا باشد، خطای فارسی درست است — فایل منبع را بررسی کنید؛ سیستم عمداً خروجی جعلی نمی‌سازد.

## ۶. خرابی GPU/CUDA

- رفتار پیش‌فرض: fallback خودکار به CPU (کندتر). رندر NVENC نبود → x264. هیچ کاری لازم نیست.
- رفع واقعی: به‌روزرسانی درایور NVIDIA از سایت رسمی (نیازمند ری‌استارت ویندوز — خارج از وظایف خودکار).
- سلامت GPU در صفحهٔ خدمات: «ok» یا «limited» — limited یعنی همین حالت جایگزین فعال است.

## ۷. از دست رفتن تنظیمات (config/env)

- **`.env` (کلیدهای سرویس‌ها):** جایگزینی ندارد؛ کلیدها را دوباره از سرویس‌دهنده بگیرید ([CREDENTIAL-ONBOARDING](CREDENTIAL-ONBOARDING.fa.md)). Secretها هرگز در git/پشتیبان/دیتابیس ذخیره نمی‌شوند — پس از پشتیبان هم برنمی‌گردند.
- **مدل Whisper/تنظیمات پنل:** در دیتابیس ذخیره می‌شوند و با پشتیبان برمی‌گردند.

## ۸. نصب ویندوز جدید / کامپیوتر جدید

1. پیش‌نیازها: `setup\Setup-TolidMohtava.ps1` (Python، FFmpeg، کتابخانه‌ها) + LM Studio + مدل‌ها.
2. مخزن: `git clone https://github.com/DashSaman/Tolid-mohtava.git` یا بازکردن پشتیبان کد.
3. داده‌ها: پشتیبان `tolid-...` را برگردانید (`Restore-TolidMohtava.ps1 -From ... [-WithMedia]`).
4. کلیدهای سرویس‌ها را دوباره در `.env`/متغیرهای کاربر بگذارید.
5. `Open-Panel.cmd` ← صفحهٔ سلامت همه‌چیز را تأیید می‌کند.

## ۹. بازگردانی از پشتیبان (خلاصهٔ آزمون‌شده)

```powershell
# بستن پنل، سپس:
powershell -ExecutionPolicy Bypass -File setup\Restore-TolidMohtava.ps1 -From outputs\backups\tolid-20260929-220344
# با رسانه‌ها: -WithMedia
```
- آزمون‌شده: integrity + مطابقت محتوا (جلسهٔ closeout، نتیجهٔ PASS).
- نکته: پشتیبان بدون `-IncludeMedia` رسانه‌های RAW را ندارد؛ خروجی‌های رندر هم دوباره قابل ساخت‌اند از همان RAWها.

## چه چیزهایی بازیابی‌پذیر «نیست»

- Secretهای سرویس‌ها (عمداً هیچ‌جا ذخیره نمی‌شوند).
- پروژهٔ حذف‌شدهٔ قطعی، جز از پشتیبان قبلی.
- پست‌های منتشرشدهٔ بیرونی اگر خود سرویس‌دهنده حذفشان کند (خارج از کنترل سیستم).
